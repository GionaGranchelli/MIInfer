# EXP-0045 — M6-A3 Qwen3.8-27B single DeltaNet layer

## Question

Can MIInfer reproduce one real Qwen3.8-27B Gated DeltaNet layer from the
pinned external reference, including state evolution across multiple token
positions?

## Hypothesis

The Qwen3.8 layer-0 recurrent path can be reconstructed from the GGUF tensor
layout and validated independently before adding a GPU executor or full-model
planner.

## Reference and artifact

* model: `/home/fedora-workstation/models/Qwen3.8-27B-Q4_K_M.gguf`
* size: 17,106,775,008 bytes (15.93 GiB)
* SHA-256: `7e78da5d7e3ae28d178121f58646953305f3e5bd3cb46f4a75584e8b6c6fe169`
* reference: llama.cpp commit `c0bc8591e8815c63cb01dd3f051a8b0df02501c9`
* fixture: `/tmp/m6a1-qwen38-reference`
* workload: prompt `hello`, token `[14556]`, positions `0,1,2,4,8`

The fixture exporter was extended to retain the layer-0
`linear_attn_qkv_mixed` F32 checkpoint. The fixture remains generated by the
same pinned CPU llama.cpp reference.

## Candidate

`tools/m6a3_qwen35_layer.cpp` is a host-only, tensor-first harness. It reads
the real GGUF directly and validates:

* Q4_K embedding and attention RMSNorm;
* Q6_K QKV projection and layer-0 convolution;
* SiLU, Q/K L2 normalization, Q-to-V head repeat;
* beta/gate projections and gated DeltaNet state update;
* recurrent output and gated output;
* at position 0, SSM output projection, residual, post-attention norm, FFN,
  and layer output;
* state continuity from position 0 to 1 and position 1 to 2.

No production model loader, HIP kernel, or full-model dispatch was changed.

## Commands

```bash

cmake --build build/host-only --target miinfer-m6a3-qwen35-layer -j2
```

* attention residual: `1.91e-5`

* FFN output: `1.80e-5`
* layer output: `9.89e-6`

## Interpretation

The Qwen3.8 layer-0 DeltaNet math and the relevant real GGUF tensor layouts
are understood well enough to proceed to a GPU implementation. The
convolution checkpoint initially exposed a layout error: the `[4, channels]`
F32 kernel is stored as four contiguous coefficients per channel, not as four
channel-sized planes. Correcting that produced the reported agreement.

Positions 4 and 8 use the external `conv_output_raw` checkpoint because the
fixture does not retain every intermediate token needed to reconstruct the
four-token convolution history. Their recurrent state/output checks remain
valid against the corresponding external checkpoints.

The harness uses a reference-compatible host Q8_K matvec path for quantized
GGUF projections. This is a correctness aid, not a production performance
implementation.

## Decision

**KEEP / M6-A3 complete for host bring-up.** The single real recurrent layer,
including state mutation and the position-0 FFN tail, passes the pinned
external fixture. MI50/GPU execution is intentionally not claimed complete.

## Follow-up

Proceed to M6-A4: implement and validate one real full-attention layer using
the same fixture/reference discipline. Then compose the verified recurrent
and full-attention paths into the actual hybrid block.
